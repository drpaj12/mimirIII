# Mimir remote data: a committed index of the offloaded data, and `mimir fetch`

Purpose (Peter 2026-10-27): the data behind Mimir (the F: archives, the xz blob store, the snapshots) will get a web
path. The mimirIII repo alone must then be able to fetch any single file for a detailed look. This serves the dataset
core (every value says how it was obtained, down to the raw file) and Mi Q1.3 (is the import complete).
Measures: index coverage (every blob a store row references resolves to an index entry; target 100%), fetch
correctness (a fetched file's sha256 equals its manifest sha256), index size (a few MB compressed).

## 1. The committed index, `data/remote/`

- `archives.toml`: one `[[archive]]` per archive, generated by `mimir remote index` from the archive directory.
  Fields: `name`, `date` (the dated dir), `file` (a `.tar.xz`, or the dir name for a snapshot), `form` (`tar.xz` or
  `dir`), `kind` (`loki-data`, `norns-runs`, `odin3-work`, `blobs`, `snapshot`, `originals`, `papers`), `source`
  (`~/odin3-ws/work/<dir>`, informative), `manifest`, `visibility` (`public` or `private`), `licence` (see 3),
  `sha256` and `size` of the file (a `dir` has an empty sha256; its members are checked one by one), `members`
  (regular files), `urls = []` (empty until Peter gives a web path), and the repack record (`public_*`, empty until
  the archive is repacked for hosting): `public_file`, `public_sha256`, `public_size`, `public_manifest`,
  `public_members`, `public_dropped`, `public_scrubbed`, and `master_sha256` is the `sha256` field.
- `manifests/<name>.tsv.xz`: the F: manifest, normalised: `path<TAB>type<TAB>size<TAB>sha256`, type `d`, `f` or `l`
  (archives 1-2 write `dir`/`file`/`link`, archive 3 writes `d`/`f`/`l`; both are read), sorted by path, a link's last
  field is its target. The home dir in a target is written `$HOME` (`$WS` for the workspace). Archives without a F:
  manifest (`mimir-meta-papers`, the blob tarball, the snapshot dirs) get one built by reading them.
  `manifests/<name>.public.tsv.xz` is the manifest of a repack.
- `blobs.tsv.xz`: `sha256<TAB>xz_bytes<TAB>archive` for every blob of the store; `archive` names a blob tarball that
  holds it as `blobs/<ab>/<sha>.xz`, or `-`.
- `licences.toml`: the reviewed copy of the controller's per-archive verdicts (section 3).

A private archive (`mimir-meta-papers`, `mimir-mcnc-originals`, `mimir-mcnc-originals-r2`, the superseded snapshot
`mimir-snapshot-2026-10-27`) is never given a URL, never staged, and `mimir fetch` refuses to download it.

## 2. Locations and `mimir fetch`

- `MIMIR_BLOBS`: the local blob store (as before). `MIMIR_ARCHIVE`: a dir that holds archives (F: is one), searched as
  `<dir>/<file>` and `<dir>/<date>/<file>`. `MIMIR_DATA_URL`: a base URL; it replaces `urls` of the TOML. Without it,
  an archive is fetched by URL only when its `urls` is non-empty; `--online` uses the default base
  `https://drpeterjamieson.com/RESEARCH/MIMIR/mimir-data`. `MIMIR_CACHE`: the cache dir (default
  `$XDG_CACHE_HOME/mimir`, else `~/.cache/mimir`; never inside the repo).
- `mimir fetch ARCHIVE:MEMBER`, `mimir fetch --sha SHA` (a blob, else the first manifest member with that sha256),
  `mimir fetch --run RUN_ID --db DB` (every artifact of a run). `--out` names the file (`--sha`, `ARCHIVE:MEMBER`) or
  the directory (`--run`); without it the file lands in the cache and its path is printed.
- Order: the local blob store (blobs), `MIMIR_ARCHIVE`, the cache, the URL. A URL serves the public repack; a local
  archive is the master, and each is checked against its own manifest.
- The archive's sha256 is verified before use (a marker in the cache skips a repeat), the member's sha256 and size
  after extraction. A mismatch is an error and nothing is written. One member is read from the stream. A member
  that is absolute, has `..`, is a link, a device or a directory is refused, and the tarfile `data` filter runs.
  Downloads are untrusted data: they are only hashed and copied, never run. A download goes to `<name>.part` and is
  renamed on success; a failed download is truncated and left in place (nothing is deleted).
- Schemes: `http`, `https`, `file` (tests use `file://`).

## 3. Licences, publish-plan and the public repack

- Every benchmark keeps the licence it states (or `none-stated`); nothing is relicensed. `licences.toml` holds, per
  archive: `verdict` (`host`, `host-with-notices`, `split`, `do-not-host`), `sources`, `licence_refs`, `notes`, `drop`
  (extra member globs to drop) and `texts` (licence texts shipped). Archives the controller table does not cover get a
  derived entry (`basis = "derived"`).
- An archive's licence is its verdict, or `pending` when a design in it has no licence meta. A design is found in a
  manifest by the rules of `data/meta/licences.toml` (a path component equal to the benchmark name, or starting with
  the prefix of a wildcard rule). `NOTICE` lists, per rule hit, the design, licence, source and notice from that file.
- `mimir remote publish-plan` uploads nothing. It prints, per hostable archive, the file name and size, and scans each
  public archive's manifest for `/home` paths and `.pdf` members. It refuses a private archive, and a `pending` one
  without `--allow-pending`. `--stage DIR` writes the tree `<date>/<archive>.tar.xz`, `<date>/SHA256SUMS`,
  `blobs/<ab>/<sha>.xz`, `index/archives.toml` and a `README.txt` (copies, not links).
- A public archive is a repack of the F: master (which stays unchanged), streamed through `xz -T2`: it drops links,
  `.venv/`, `__pycache__/`, `*.pkl`, `*.db`, `*.lock`, `*.sh` and the archive's `drop` globs; it scrubs `/home/<user>`
  to `$WS` (`$HOME`), and the user name, in every text member (a `.gz` or `.xz` member is decompressed, scrubbed and
  compressed again); a binary member with a hit is dropped and listed. It adds `NOTICE` and the licence texts, and
  writes the new manifest. `--record` writes the repack fields into `archives.toml`.

## 4. `mimir remote check`

For every column named `*blob*` of every table of the store (today `run_artifact.blob_sha256`,
`partition.assignment_blob`, `analysis_result.labels_blob`), count the distinct non-empty references that resolve to
a `blobs.tsv.xz` entry. Output: per table and column, references, resolved, missing, then the missing shas. Exit 1
on any miss.
