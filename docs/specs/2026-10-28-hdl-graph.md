# Line-level HDL graph (schema version 7)

Date 2026-10-28. Branch `feat/hdl-graph`. Additive on version 6 (`2026-10-28-timing-paths.md`).
Purpose: hub RQ W Q3.3 (Wyrd visualises the dataset); a viewer can walk from a source line forward to
the primary outputs it reaches and backward to the primary inputs that feed it. Measure: speed
(cones around the critical and near-critical paths).

## 1. Source of the graph

A run's stored `blif` and `map` artifacts (sha256 checked). Each primitive of the top model is an
atom (`structmap.atom_candidates`, shared with `atoms_from_blif`). Its source location is Odin III's
own atom to span provenance, `timing_attr.Resolver` of `<odin3 tree>/tools/flow` (the code the timing
attribution uses; not re-derived), so a node is the same `(file:line, module, word, bit)` as a node of
a `timing_path_node` row. The edge A to B exists when a net driven by atom A is read by atom B.
Clock pins are not data. An atom the name map does not hold has no location: the graph passes
through it (its fan-in joins its fan-out); a chain of such atoms does not cut a cone.

## 2. Tables

    hdl_graph_run(run_id PK, n_atoms, n_unattributed, n_edges, n_ports, blif_sha256, map_sha256)
    hdl_edge(run_id, src_span, src_module, src_word, src_bit, dst_span, dst_module, dst_word,
             dst_bit, via_register, PRIMARY KEY over all)
    hdl_port(run_id, span, module, word, bit, kind CHECK IN ('PI','PO'), port, PRIMARY KEY ...)
    indexes: hdl_edge(run_id, src_span), hdl_edge(run_id, dst_span)

- `span` is `file:line` as in the attribution (`$VTR_ROOT` kept); `bit` is -1 when the origin gives
  none. Edges are deduplicated over these columns; an edge whose two ends are the same node and
  not through a register is dropped.
- `via_register` = 1 when the signal leaves a register: the source atom is a flip-flop, or the
  source is reached through an unlocated flip-flop. A walk that does not cross registers does not
  take such an edge forward; backward it takes it, adds the source as an end node and does not go
  beyond it. A walk that crosses registers takes every edge.
- `hdl_port`: PI rows are the top model's `.inputs` that the map locates (the declaration line);
  PO rows are the `.outputs` whose driver atom has a location (the span of the driving atom: output
  pads carry no source line). `port` is the port bit name (`oport_get[3]`); `word`/`bit` are those of
  the located node, so a port row joins an edge node.
- Texts pass the `Scrubber`; a /home path stops the run's write. Host-alias scrubbing lists the
  columns (`hostscrub`).

## 3. CLI

`mimir hdl-graph STORE [--odin3-tree DIR | $MIMIR_ODIN3_TREE] [--blobs DIR] [--run ID]` builds the graph
of every run that has a blif and a map artifact and no `hdl_graph_run` row; idempotent; writes only
these three tables. `mimir migrate` takes a version 4 to 6 store to 7; versions 4 to 6 open read
only as they are (`hdlgraph.has_tables`). Back the store up first.

The tests use the vendored `timing_attr.py` and `timing_report.py` beside `name_map_v2.py`
(`tests/fixtures/deps`).
