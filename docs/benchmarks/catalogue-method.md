# Catalogue method

Build names used below are local names of Odin III builds: `rel-main2` = Odin III 1.2.0 (commit in `opencores.md`), `rel-main3` =
1.4.0, `rel-v160` = 1.6.0 (main, not yet tagged on 2026-11-09). What changed in the catalogue, by date, is the dated sections of this page.

Table: `docs/benchmarks/catalogue.md` (also `data/benchmarks/catalogue.tsv`). Generator: `mimir bench catalogue`.
Inputs: the registry plus `data/benchmarks/measures.tsv` (`suite design key value source`, one row per
value, the source says where it came from). Collectors: `mimir bench measure vtr|silicon|testbench`; Odin III
runs are added by `mimir bench measure odin` (Phase 2, below). Empty cell `-` = not run, `n/a` = does not
apply, `fail: <reason>` = the tool failed. No value is estimated.

Rows: 513 = one per design of `designs.tsv`, except that `vtr-blif-k2` and `vtr-blif-k4` hold the same
circuits and are one section, one row per circuit name present in either (rule: equal design name; 199
names; format column says `blif (k2,k4)`). Values for a joined row are looked up in k4 first, then k2.

## Columns and sources

- LOC: `lines` of `designs.tsv` (Verilog); `-` for BLIF.
- testbench: path (relative to `external/`) of a `tb_*`/`*_tb*`/`*_test*` file named for the design in the
  suite directory, else a cross (searched only the suite directory; VTR and ITC'99 ship none). VerilogEval:
  `<problem>_test.sv`. BRISC-V: `tb_single_cycle_BRAM_top_gcd.v` in the project dir.
- vectors: tick when that testbench compares against a reference module (VerilogEval: the testbench
  instantiates the reference `RefModule` and drives stimulus) or reads a stimulus/expected file
  (`$readmemh`, `$readmemb`, `$fscanf`); else cross. BLIF circuits ship none.
- VTR path (one sample): the Norns run record `norns-placers-e10-base`, arm `vpr_sa`, seed 1, architecture
  `k6_frac_N10_frac_chain_mem32K_40nm`, VTR commit `3c9a4d23b2` (VTR 9, Peter co-author of the 2012 VTR paper;
  both cited in `citations.toml` where the project cites VTR). LUTs = `struct.n_comb`, blocks =
  `vpr.blocks` (all blocks: CLBs, I/O, hard blocks), cpd = `vpr.cpd` (ns), chan w = `vpr.chan_width`.
  FFs, pins (BLIF `.inputs` + `.outputs` bits of the top model), mult/mem hard blocks (`multiply`;
  `single_port_ram` + `dual_port_ram` `.subckt`) are counted from the mapped BLIF blob of the same
  design and flow (`odin3-1.2.0-k6-verilog` or `-blif`). Only the 35 designs of that run are filled.
- Silicon path: run root of Q-L13 (44 designs: 40 VerilogEval problems and 4 processor modules; the 4
  modules are not registered designs and are not in the table). stage = last step with status ok of
  read, elab, map, netlist, equiv, place, route, gds, extract, lvs. LVS = `match` when the lvs step is
  ok, `mismatch` when it failed with a netlist mismatch, else `out of scope: stopped at <step>
  (<reason>)`. cells = instances at the end of detailed route (`census.json` step `s10_detail_route`,
  including tap cells and CTS buffers, without fill). core um2 = OpenROAD `CoreArea` (GPL-0016) / 1e6
  (DBU 1000). Not run here; no design outside Q-L13 has a silicon row.
- property checks and gates / 4-LUT / 6-LUT: Odin III (Phase 2).

Read-only inputs: store `e10.db`, blob store, `ql13-out`, the external checkouts.

## Notes

- `tinyriscv_clint`: its `raddr_o` output is declared but never assigned upstream (`clint.v` line 56),
  which is why the Q-L13 equivalence step reported an undriven output for it. (The four processor modules
  of Q-L13 are not registered designs.)
- README: the block between the `catalogue:start` / `catalogue:end` comments is regenerated by
  `mimir bench catalogue --readme README.md`; nothing else in the README is touched.
- BRISC-V is read as the 31 `.v` files of the project dir without the testbench (`tb_*`) and the Quartus
  black-box stub `pll_clock_bb.v` (it redefines `pll_clock`), with `read_verilog --auto-blackbox` so the
  vendor `altpll` primitive becomes a black box (a `bbox` tick); no other design is read with that flag.
- Absolute paths in an Odin III error text are cut to the file name before they are stored.

## Store data used (`mimir bench measure store`, source `store ...` in measures.tsv)

- VTR path, 15 `vtr-verilog` and 20 `mcnc20` designs: the Norns e10-base run (seed 1, arm `vpr_sa`), see
  above. The same 15 Verilog designs are also in the store under `norns-r1r2`, `norns-r3` (arm
  `stock/seed`) and `norns-r4`; one sample is shown per design, and the e10-base one is the rule because it
  is the only run with all 35 designs, one flow and one architecture. The 16 other `vtr-verilog` designs
  have no VPR record in the store; they were run with `mimir bench measure vpr`: `odin3-flow` (Odin III
  `rel-main2`, then VPR at the minimum channel width, same architecture, seed 1, VTR commit as above) in one
  `heavy-run` slot, smallest source first. luts = `.names` with two or more inputs of the mapped BLIF
  (`odin3-flow` `luts`, not `struct.n_comb`), blocks = `Netlist num_blocks` of `vpr.out`, cpd and
  channel width from VTR's parse; FFs, pins, hard blocks from the BLIF as above. `vtr_stage` is `route`
  when the flow finished; a design that hits the 3600 s Odin III or 7200 s VPR step limit or the 6 GB
  slot cap is recorded `<step>: too big for now (...)` in `vtr_stage` and `fail: ...` in the other VTR
  columns. Nothing hit a limit in this run.
- 6-LUT count of the 150 VerilogEval designs with a Loki record: Loki floor `f2` (`lower; abc --lut 6`
  after the same front passes as the 6-LUT run here, store source `loki:loki-veval-exp/dataset`, metric
  `loki.luts`). The Odin III version of that run is not recorded. A fresh Odin III 6-LUT run never
  overwrites a store-sourced value.
- 4-LUT count and logic depth of `vtr-blif` (k4) and `mcnc20` circuits: the shipped 4-LUT mapped BLIF as
  Mimir measured it (`struct.n_comb`, `struct.depth`, sources `mcnc-k4` and `mcnc`), not an `abc --lut 4`
  remap. `blif/2` (k2) is not measured separately: a row with a k4 circuit takes k4 values.
- For BLIF circuits "gates" are the `.names` nodes as shipped (`$sop` cells that `read_blif` creates).

## Tiers and order (rules use measured columns, never the suite name)

| tier | rule |
|---|---|
| T0 whole flow | T1 rule, and `sim_iverilog` = `pass` and `sim_odin` = `pass` and `vtr_stage` = `route` or `timing` |
| T1 HDL + testbench, larger | format Verilog, a testbench file (`tb` not 0), LOC >= 200 |
| T2 HDL + testbench, small | format Verilog, a testbench file, LOC < 200 |
| T3 HDL, no testbench | format Verilog, no testbench file |
| T4 netlist only | format BLIF |

Size threshold: 200 Verilog lines (`lines` of `designs.tsv`; a project is its total). Within a tier: rows
with a testbench first, then rows with a LUT count before rows with only LOC; LUT count = `l6_luts`, else
`vtr_luts`, else `l4_luts`; largest first; design name breaks ties (then suite). Keys the T0 rule needs, to be
written by the opencores intake lane or any later collector: `sim_iverilog` (`pass` = the design's own testbench
passes in iverilog; `fail`, `none` = no testbench, `refused`; as stored in `measures.tsv`), `sim_odin` (`pass` = passes in Odin III `sim_tb`/`run_testbenches`; same values),
`vtr_stage` (deepest VTR stage reached: `elab`, `map`, `route`, `timing`; `route` and `timing` both mean routed with
timing analysis: `route` is written by `bench measure vpr`, `timing` by the odin3-flow collectors; `none` = failed). `catalogue.tsv` has `tier` and `rank` as its first two columns.

`desc` (what it does) sources: VerilogEval, the sentence after "The module should implement" in
`<problem>_prompt.txt`; VTR Verilog, the Domain column of the VTR 7.0 benchmark table in the VTR docs
(`doc/src/vtr/benchmarks.rst`; 19 of 31 designs are listed); MCNC circuits, `intent` of `data/meta/mcnc.toml`
up to its first parenthesis; BRISC-V, the suite title. ITC'99 and the other BLIF circuits: `-`, the sources
read say nothing per circuit. Each `desc` row's source field names the file. Collector: `mimir bench measure
desc`.

BRISC-V: the first Odin III run was stopped by my 1500 s wall limit with no values; its checks and counts
are `-` until rerun with longer limits.

## Layout

- GitHub tables are narrow: per tier, an Overview table (design, what it does, suite, link, licence, LOC,
  testbench, vectors) and, folded in `<details>`, Flow and VTR QoR, LUT forms, Properties and Silicon. Every
  table has `design` first and the same rows in the same order. Long values are cut to 30 characters there;
  the full text is in `catalogue.tsv` and in the HTML page.
- `docs/benchmarks/catalogue.html`: one wide table, sticky header row and first column, a scrollbar above
  the table that follows the one below, sortable columns, filter box. Inline CSS and JS only, no network.
  GitHub Pages serves it at https://drpaj12.github.io/mimirIII/benchmarks/catalogue.html (Pages is on, main,
  `/docs`; `docs/.nojekyll` keeps Jekyll from processing the markdown there).
- link = the `link` measure if present, else the suite's upstream URL; licence = the `licence` measure, else
  the licence name at the head of the suite's `licence` text in `suites.toml`.

## Run order and limits

Every pass runs smaller designs first (source bytes, ascending) and suites from small to large; BRISC-V
(4349 lines) goes after the small suites. One Odin III run is limited to 900 s (and the heavy-run slice
memory cap). A design that hits a limit is recorded as `fail: too big for now (timeout 900 s, last finished
pass <name>)` and the pass goes on with the next design.

## Power columns (Bifrost III, 2026-11-08)

Purpose: hub B Q1.2 (can recorded activity feed a power estimate of the placed and routed design), measure =
power. Collector: `mimir bench measure power --root <dir of <design>/power.json> --label <run name>`; the
`power.json` files are written by `wyrd power run` (Wyrd repo, `docs/specs/2026-11-06-bifrost-power-design.md`).
Columns (energy per clock cycle = power x the clock period of its own target, so FPGA and ASIC compare as
energy, not power; compare trends, not absolute pJ across technologies):
- `pw_src`: where the switching activity came from: `iverilog-gate` (the design's testbench on the
  post-synthesis netlist, in iverilog), `odin3-sim` (Odin III `sim_tb --vcd-all`), `ace2` (vectorless: ACE2
  with its defaults, primary-input static probability 0.5 and switching activity 0.2, seed 1).
- `pw_fpga_pjc`: FPGA energy per clock cycle in pJ (VPR `--power`, PTM 45 nm, channel width 100, the k6 40 nm
  architecture; the clock period is VPR's critical path). `pw_freq_mhz`: that frequency in MHz.
- `pw_asic_pjc`: ASIC energy per clock cycle in pJ (OpenROAD/OpenSTA, sky130_fd_sc_hd tt 1.8 V, placement
  parasitics, at the testbench clock period given in `pw_note`). `-` where there is no silicon run or no
  gate-level testbench for it.
- `pw_note`: matched-net fraction (nets of the netlist that took a measured activity; the rest take the mean),
  testbench cycles or the ACE2 defaults, the ASIC clock.
`-` = not run. Known limit: VPR's power model has no `adder` model, so soft-adder carry chains add no power in
the FPGA figure.
`--suite S` resolves a directory name that exists in several suites to S (`des` is in four; the Bifrost run is the
OpenCores one: `--suite opencores`). The 15 Odin III micro designs (`bm_*`) of the power runs are the
suite `odin3-micro` (all 58 `bm_*.v` of the VTR odin_ii regression micro directory are registered; the 15 have power
rows and Heimdall III pages).

## Vectorless activity columns (Odin III, 2026-11-09)

Collector: `mimir bench measure activity --root <dir of <design>/odin3-activity.json> --label <run and Odin III version>`.
The files are `odin3 activity --name-style hash --json` of the design's mapped netlist (Odin III 1.6.0, rel-v160;
analytic, no vectors; primary inputs P1 0.5, density 0.2). Columns (table group `Power`):
- `pw_vl_p1`, `pw_vl_d`: mean P1 and mean transition density over all nets of the file (primary inputs included),
  4 decimals. `pw_vl_nets`: the net count. `pw_vl_src`: source label and the primary-input settings.
The measures `source` field names the run, the Odin III version and the file. These are activity statistics, not
a power claim; the power columns above stay Bifrost's (power tracks area; no new power claim is made here).
Filled for the 53 designs that have an `odin3-vectorless` result among the Heimdall III pages.

## Tier fix and Odin III 1.6.0 re-measure (2026-11-09)

- The T0 rule compared `sim_iverilog` and `sim_odin` with `1` and `vtr_stage` with `route`; `measures.tsv` stores
  `pass` / `fail` / `none` / `refused` and the odin3-flow collectors write `timing` for a routed run with timing, so
  T0 was always empty. The rule now reads the stored values: `pass`, `pass`, and `route` or `timing`.
- `sim_odin` of every Verilog design with a testbench and 200+ lines was re-run with Odin III 1.6.0 (commit
  `d0649167`, `rel-v160`): `sim_tb` of the project testbench, 1800 s limit (1200 s for dblclockfft and wb_lcd, which passed in 1171 s and 61 s); the
  `source` field of each row names the run. `sim_iverilog` does not depend on Odin III and is unchanged.
  There is no `mimir bench measure` collector for `sim_odin`; the rows are written by the run scripts of the OpenCores lane.
