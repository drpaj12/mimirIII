# I8: TreeLUT (gradient-boosted trees as LUT logic)

Source: `https://github.com/kiabuzz/TreeLUT` at commit `ad9e70a9ba1a74ccf8df97a3f7fcdc9137e68b21` (MIT,
Copyright (c) 2024 Kia Bazargan). Read by path, pip-installed into the one venv (see `I6-NEURALUT.md`),
never copied. A different model from the reference LeNet-5: an XGBoost classifier (10 classes, `n_estimators`
trees per class) converted by TreeLUT's toolflow into Verilog: every split `feature < threshold` becomes a
comparator, every tree a small priority-if block with a `w_tree`-bit leaf, then a per-class adder tree and an
argmax. Scored on top-1 against the MNIST labels, not against Gabe's golden.

## Input transform (the wrapper)

The testbench streams the int8 pixel `q` of `docs/INTERFACE.md`. TreeLUT's own example uses a per-pixel
MinMaxScaler on the raw 0..255 pixel; that value is not on the stream, so the model is trained on
`feature = clip(round((q + 19) * (2^w - 1) / 146), 0, 2^w - 1)` (one global map; 19 and 146 are the range of
`q` over MNIST: `q(p=0) = -19`, `q(p=255) = 127`). Training uses the 60,000 MNIST training images mapped the
same way (`tools/lutnn_common.py`). The map is a ladder of `2^w - 1` constant comparators on the streamed byte
(counted in the wrapper). Only pixels some tree reads are stored (`pixels_used` of 784), `w` bits each, in a
shift register that shifts only when the current pixel position is used (a 784-entry ROM of used flags).

## Wrapper `mnist_top` (ours, generated by `tools/treelut_gen.py`)

Pixel counter, used-flag ROM, feature ladder, feature shift register, TreeLUT's `TreeLUT` module, a 10-way
argmax chain (first maximum wins), result registers. `done` rises `784 + 1 + L + 1` clock edges after `start`
(`L` = TreeLUT pipeline stages = `sum(pipeline)`), so cycles per image are 786 (L = 0) or 788 (L = 2).
Pipelining is TreeLUT's `pipeline=[features, trees, adders]` register option; it adds no initiation-interval
gain here because the wrapper loads one image at a time.

`scores` mapping: TreeLUT's class sums are unsigned `sum_bits` wide (5 to 9 bits), not int8 class scores. The
wrapper drives `scores[8k+7:8k]` with the low byte of sum k (wiring only, no logic). The per-model vector files
carry the same low bytes, so `score_match` checks the sums modulo 256 in simulation.

## Settings and results

| setting | w_feature | w_tree | trees / class | max depth | eta | pipeline | pixels read | unique (feature, threshold) | sum bits |
|---|---|---|---|---|---|---|---|---|---|
| T1 (their MNIST example) | 4 | 3 | 30 | 5 | 0.8 | [0,1,1] | 509 | 3,798 | 7 |
| T2 (smaller) | 3 | 2 | 15 | 4 | 0.8 | [0,0,0] | 457 | 1,267 | 5 |
| T3 (larger) | 4 | 4 | 60 | 6 | 0.6 | [0,1,1] | 533 | 5,209 | 9 |

Training (XGBoost, CPU, 4 threads, `random_state=0`): 9.8 s (T1), 4.4 s (T2), 21.7 s (T3). Float XGBoost top-1
on the 10,000 test images: 96.93 %, 94.99 %, 97.66 %. After TreeLUT quantisation (the model the Verilog
implements): 96.26 %, 90.64 %, 97.64 %.

See `RESULTS-LUT.md` for the simulation, area, speed and power tables (rows from `score/lut_table.py`).

## Method notes

- Python model vs Verilog: the converted model's per-class sums (TreeLUT's `_single_tree_predict`, plus its
  class biases) give class and sum bytes for the first 100 and all 10,000 test images
  (`tools/treelut_gen.py` writes them as the vector files); the testbench checks the Verilog against them.
  `TreeLUTClassifier.predict` and the sums agree on 10,000 / 10,000 images.
- Simulators: the full tier (10,000 images) and the quick tier (100) run on Verilator. iverilog on the quick
  tier did not finish T2 in 25 minutes (it needs 2.7 minutes for NeuraLUT B), so the quick tier is Verilator
  too; the quick-tier netlist check is Odin III `sim_tb` (below).
- Odin III netlist check: `abc --lut 6` netlist, `sim_tb` on the first 100 images, class and score match.
- Generated Verilog is not committed. `tools/treelut_gen.py <setting> <build_dir>` regenerates it; the sha256
  of the files of the run reported here are in `RESULTS-LUT.md`.
