# I3: layer-pipelined dataflow, weights in on-chip RAM

Generated by `tools/gen_lenet.py --design i3 --p P` (Python stdlib + numpy; Verilog-2005; one clock). The network is
the reference LeNet-5 (`golden/lenet_int8.py`): weights and (M0, n) are read from the pinned transmission file at
build time and written to `w_<layer>_l<lane>.hex` in the build directory (`$readmemh`); nothing generated is committed.
Registered in `implementations.toml` as `i3-df-p8`, `i3-df-p4`, `i3-df-p2`, `i3-df-p1`.

## Architecture

One stage per layer (`l_conv1`, `l_conv2`, `l_fc1`, `l_fc2`, `l_fc3`), then `l_sink` (collects the ten scores and
takes the argmax, first maximum wins). Stages are chained by activation buffers:

- Input buffer of a stage: a two-bank RAM (`abuf`, bank bit + address), one write port, one registered-read port.
  The producer fills one bank while the stage reads the other (full flags per bank), so consecutive images overlap.
- Compute: P lanes, each a 8x8 signed multiplier (registered product) plus an accumulator and a weight RAM
  (`wm<lane>`, synchronous read, depth = groups x K). A group is P output channels; channel `g*P+lane` is lane `lane`
  of group g; channels past the layer's width carry zero weights and their writes are suppressed (conv1: 6 channels,
  fc3: 10 channels, fc2: 84 channels do not divide every P). All lanes read the same input element each cycle
  (one input read per cycle, P weights per cycle). A layer needs `windows x groups x Q x K` cycles
  (Q = 4 conv items per 2x2 pool window, 1 for a fully connected layer).
- Max pooling runs on the raw accumulators: requantisation `clip((M0*acc + 2^(n-1)) >> n)` and ReLU are monotone,
  so `relu(rq(max a)) == max(relu(rq a))` bit-exactly. The window maximum is held per lane; at the window end the P
  maxima are snapshotted into a shift register and drained through ONE shared requantiser (one constant
  multiplier per stage), P cycles per window, into the next stage's buffer. Window length (4K >= 36 cycles) always
  exceeds P.
- Addresses are generated incrementally (adders and counters only, no multipliers): `pbase` (pooled position),
  `qoff` (position in the window), `koff` (kernel offset by constant steps), `wbase` (weight group).
- A stage starts a frame when its input bank is full, the downstream bank is free, and its previous frame has drained.

## Interface notes (settles the open item of docs/INTERFACE.md)

- `start` may be pulsed while the previous image is still in flight: the wrapper latches it (`armed`) and raises
  `in_ready` when stage 1 has a free bank. `in_ready` depends on registers only.
- `done` is a level. It drops at `start` AND at the start of each result's argmax (so every result produces one
  rising edge); `pred` and `scores` hold the last result. The common testbench is unaffected.
- Latency = `cycles_per_img` of the common serial testbench. Initiation interval (II) = steady-state cycles between
  consecutive results, measured by `tb/mnist_tb_pipe.v` (images streamed back to back; same compare against the
  golden; summary line adds `ii_cycles` and `latency_first`). Stored as `speed.ii_cycles` in the result row; the
  row's `images_per_s` is `1 / (ii_cycles x critical path)`; energy per image stays power x latency (an upper bound
  for a full pipeline).

Odin III `sim_tb` on the 100-image quick tier was NOT run: `lower` turns every memory into flip-flop bit cells (P=4:
430,479 bit cells in `l_fc1` alone), which gives about 33 cycles/s on the whole design, so 100 images (2.5 million
cycles) would take about 21 hours. The netlist (`abc --lut 6`) simulation was not run for the same reason.
Wall times of the Verilator full-tier runs: serial 148 / 275 / 479 / 877 s, pipelined 71 / 129 / 222 / 396 s
(P=8/4/2/1).

## Odin III gaps found (for an Odin lane)

1. LPM flow, read-only memories: in the `cyclonev-lpm` netlist only the five activation buffers become `altsyncram`
   (5 at every P); the `5 x P` weight memories (`reg [7:0] wm<lane> [0:D-1]` with `initial $readmemh`, one
   synchronous read, never written) are turned into logic (P=4 netlist 2.86 MB, `l_fc1` about 49,600 lines). The VTR
   flow maps the same memories to RAM blocks (28). Expected: a ROM `altsyncram` with an initial-contents file.
   Location in Odin not investigated.
2. `sim_tb` speed: memories are lowered to flip-flops (`lower: '$mem' ... lowered to 2048 flip-flops`, info lines
   `reads of addresses past SIZE ... give x`), so large RAMs make simulation too slow for the quick tier (above).
3. Lint note on the generated Verilog (not an Odin gap): iverilog warns `Numeric constant truncated to 10 bits` for
   P=8 on a constant in a branch that is never taken (conv1 has one group at P=8).
No Odin error was hit: signed multiply, `>>>`, `$readmemh`, inferred dual-port RAM, `proc; opt; lower; sim_tb` and
`--top mnist_top` all worked.

## Deviations

- The pipelined tb is an added testbench (`tb/mnist_tb_pipe.v`); the common `tb/mnist_tb.v` is unchanged.
- Netlist-level (post-synthesis) simulation of the full design was not run (Odin cost above); the LPM netlist is not
  simulated here (needs Altera models).
- Energy per image uses latency, not II.
