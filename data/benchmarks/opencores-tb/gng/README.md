# gng testbench

tb_origin: `mimir-written` (self-checking, replaces the project's `tb/tb_gng.sv`, which writes a file
and checks nothing). Not `upstream`: the project's testbench needs a vendor ROM and MAC that the project
does not ship, and has no check.

The project RTL (`rtl/gng.v`, `gng_ctg.v`, `gng_interp.v`, `gng_lzd.v`, `gng_smul_16_18.v`, LGPL 2.1 or
later) is not copied here. Two modules the project lacks (vendor-generated cores, named in
`syn/ise` and in `sim/modelsim/run.do`) are provided as behavioural models, both ours (Mimir repo licence):

- `gng_coef.v`: the 256-word coefficient ROM (c0 u18, c1 s18, c2 u17, one cycle read latency). Source of
  the numbers: the `C0`, `C1`, `C2` tables of the project's own `c/icdf.c` (248 entries each; the 8 words
  past the end read 0 and are never addressed). Generated by `gen_gng_vectors.py`, which reads
  `icdf.c` and types in no number.
- `gng_smul_16_18_sadd_37.v`: p = a*b + c, 3 cycles, c taken one cycle after a/b. The project does not
  state this; it is the only latency/alignment consistent with `gng_interp.v` (`x_r4`, `c1_r1`), and a
  wrong choice fails the comparison below (mutation test: adding 2^20 to c gives 45 errors).

Reference: the project's C model (`c/taus176.c`, `c/icdf.c`) ported to Python in `gen_gng_vectors.py`.
The port was compared with the project's C compiled with gcc on all 8192 + 1550 vectors (identical);
that comparison needs gcc and is not part of the CI tests. `tests/test_opencores_tb_gng.py` checks the
first three Tausworthe outputs and final state against the gcc-compiled C, the generator's
determinism and the vector layout.

Checks (11733; prints `PASS tb_gng checks=11733 errors=0` or `FAIL ...`, ends with `$finish`):
1. `gng` with the testbench's seeds, ce high for 8192 cycles: every sample equals the C model sequence
   (`stream_exp.hex`); the first `valid_out` comes 11 clock cycles after ce (spec section 3.5).
2. Reset again, ce 3 cycles on / 2 off: the valid samples are the same sequence from the start.
3. `gng_interp` alone with 1488 directed 64-bit words (all 62 leading-zero counts, 4 offsets, 2 signs,
   3 low-bit patterns, fixed LCG) against `icdf()` of the C model.

Finding (RTL pipeline hazard, observed not fixed): in `gng_interp.v` `mask` is registered from
`num_lzd_r` and then applied in `x_r1 <= x & mask` one clock later, so the first word after a change of
leading-zero count is masked with the previous word's mask. It matters only when the leading one falls
inside the 15 interpolation bits (leading-zero count >= 46, probability about 2^-46 per sample). Each
leading-zero group of the directed vectors therefore starts with a warm-up copy of its first word
(`interp_chk.hex` flag 0): its result is counted and printed (`INFO ... 4 of 62` differ from the C model:
counts 56..59), not checked. Every other word is checked.

Run (iverilog); the generated files and the four project `.v` files plus `gng_ctg.v` etc. in one directory:

    python3 gen_gng_vectors.py <gng>/c/icdf.c .          # writes gng_coef.v and the .hex files
    cp <gng>/rtl/*.v .
    iverilog -g2005 -s tb_gng -o sim.vvp *.v && vvp sim.vvp      # run in the directory ($readmemh paths)

Odin III (about 26 s): `odin3 -p "read_verilog gng.v gng_ctg.v gng_interp.v gng_lzd.v gng_smul_16_18.v gng_smul_16_18_sadd_37.v gng_coef.v; proc; opt; lower; sim_tb --top tb_gng --max-time 2000000 --out run.txt tb_gng.v"`
run in the directory of the hex files. Same PASS line and INFO line as iverilog.
